# 천하 개발 관측소

외부 의존성 없는 정적 공개 대시보드입니다. `index.html`을 직접 열거나 이 폴더를 GitHub Pages에 배포할 수 있습니다. 인터넷 폰트·분석기·외부 API를 호출하지 않습니다.

## 페이지

- **개발 보드**: 진행 중 / 검증 완료 / 다음 계획 / 외부 검증 대기. 분야 필터와 검색을 조합할 수 있으며 카드를 펼치면 근거와 다음 단계를 표시합니다.
- **기능과 격차**: 현재 구현과 아직 빠진 범위를 나란히 표시합니다. 보드 카드 비율을 원작 대비 완성률로 계산하지 않습니다.
- **검증 기록**: 마일스톤, M03.1 렌더 측정, M05 개별 병사 모듈 결과와 한계를 구분합니다.

현재 개발 우선순위는 기능·그래픽 확장이며 최적화를 병행합니다. M05의 개별 물리·3D 캠페인 지형·군대는 진행 중입니다. M04는 도구/정적 진단과 원작 플레이 검증 상태를 분리합니다.

## 안전한 스냅샷 갱신

전체 개발 작업 공간에서 실행합니다.

```powershell
python project_monitor/build_data.py
python project_monitor/build_data.py --check
```

생성기는 상위 프로젝트의 마일스톤 JSON과 개별 병사 검사 JSON에서 **명시적으로 허용한 숫자와 상태**만 추출합니다. 카드/격차/문장 상태는 `build_data.py`의 정제된 목록을 담당자가 갱신합니다. 문서 전체나 마일스톤 객체 전체를 직렬화하지 않습니다. 공개 스냅샷은 `monitor-data.json`과 동일 내용을 가진 `monitor-data.js`입니다. JS 사본 덕분에 `file://`로 열어도 동작합니다.

원작 설치 경로, 개인 계정/채널 정보, 비공개 영상 URL, 모드 DB 값, 원문 로그·원작 파일은 배포 대상이 아닙니다. 자동 검사 외에도 변경한 문장과 새 공개 이미지는 검토해야 합니다. `assets/battle-m03-1.png`는 검토한 독립 개발판 화면이며 M03.1의 **개별 물리 통합 전** 이미지입니다.

다른 저장소에 이 폴더만 복사한 환경에서는 상위 원문이 없으므로 생성기를 실행하지 말고 마지막 정제 스냅샷을 사용합니다. 새 검증 후 전체 개발 작업 공간에서 생성하고 결과물을 가져옵니다. M05 완료는 코드 파일 존재나 모듈 검사만으로 자동 승격되지 않습니다. 완료 범위·실제 플레이·성능·영상 근거를 검토한 후 분류와 생성기 보호 조건을 함께 갱신합니다.

## 배포 파일

`index.html`, `styles.css`, `app.js`, `monitor-data.json`, `monitor-data.js`, `.nojekyll`, `assets/`와 장수 갤러리의 `officers.html`, `officers.css`, `officers.js`, `officers.json`, `portraits/`를 사이트 루트에 배치합니다. 소스 저장소에는 이 README와 `build_data.py`도 함께 둘 수 있습니다. 인증 정보나 로컬 원문은 필요하지 않습니다. 사이트는 읽기 전용 스냅샷이며 보드에서 실제 개발 상태를 수정하지 않습니다.

## 검증

```powershell
python project_monitor/build_data.py --check
node --check project_monitor/app.js
node --check project_monitor/monitor-data.js
node --check project_monitor/officers.js
```

브라우저에서 3개 보기, 필터+검색, 결과 없음, 카드 펼침, 키보드 포커스, 모바일 레이아웃을 확인합니다. 검사 개수는 기록된 해당 범위의 검사 합이며 제품 전체의 품질 점수가 아닙니다.

장수 명부는 기본 갤러리의 12장 확대, 전체 명부의 24명 페이지네이션·마지막 페이지, 한글/한자/참고 ID 검색, 미제작·동명이인·한글 검토 필터, 빈 결과·초기화, 대화상자 닫기와 모바일 표시를 확인합니다. 1,000개 참고 ID를 1,000명의 플레이 가능한 장수로 표시하지 않습니다. 원화·모델·일기토 집계는 구별하며, 같은 이름의 ID도 합치지 않습니다. 이미지 경로는 공개 `portraits/`의 PNG만 허용하고 JSON의 등록 수와 실제 행의 집계가 다르면 오류를 표시합니다.

## M05 완료 근거

M05의 진행 중 스냅샷은 녹화 중인 파일을 읽거나 완료로 추정하지 않습니다. 완료로 바꾸려면 로컬 마일스톤 기록에 실제 MP4 경로와 SHA-256, 검토한 1080p30·60–90초 메타데이터, 화면 검토 시각 3개 이상, 캠페인·개별 전투·일기토의 성공한 캡처 보고서, 비공개 업로드 완료·확인 날짜·확인 기록이 있어야 합니다. 재촬영 보고서가 기본 M05 이름과 다르면 영상 항목의 `capture_report`로 명시합니다.

생성기는 로컬 영상 바이트와 SHA 및 이동·접촉·4장수·2인 교전의 캡처 근거를 검사합니다. 검토자의 화면·업로드 확인을 대신하는 기능은 아닙니다. 공개 결과에는 확인 여부만 쓰며 로컬 경로·계정·비공개 영상 ID를 내보내지 않습니다. `python -m unittest test_build_data -v`는 누락된 파일·변경된 바이트·공개/일부공개 업로드·없는 게임 장면이 완료로 통과하지 않는지 검사합니다.

## M05.1 동작 개선과 완료 근거

M05의 확인된 `0.4.0-dev`와 현재 제작 중인 M05.1 `0.4.1-dev`를 구분합니다. M05.1은 모델·일러스트 추가나 검사 통과만으로 완료되지 않습니다. 현재 버전의 60–135초 1080p30 MP4와 SHA, 고정 프레임·자동 명령 공개, 실제 캠페인·전투와 네 장수의 공격 구간 각각에 대한 화면 검토 시각, 비공개 YouTube 업로드 확인을 요구합니다. 재촬영은 `video.capture_report`에 기록된 별도 파일을 읽으며 중단된 첫 파일을 완료로 간주하지 않습니다.

`tests/m051_capture.gd`의 보고서는 `duel.bouts[]`에 여포·관우·장비·마초를 각각 공격자 0번으로 기록합니다. 완료 가드는 4개 서로 다른 장수 모델과 실제 4경기, 각 장수의 피해가 있는 공격, 준비·격돌 위상, 변하는 몸통·양다리·무기 방향, 실제 살아 있는 병사 표적 쌍의 위치·속도·방향·공격·준비·보행 상태와 병력 보존을 확인합니다. 빈 `contact_samples`로 과거 M05의 계측 누락을 반복하지 않도록 합니다. 이 조건은 화면의 자연스러움, 무기와 몸의 정확한 비관통, MP4 디코딩, YouTube 원격 상태를 자동 판정한다는 뜻이 아닙니다.

회귀 테스트는 기존 M05 계약 7개와 M05.1 계약 16개, 총 23개다. 테스트의 작은 가상 파일은 출처·누락·오인 완료 조건을 확인하기 위한 것으로 실제 동영상 재생 검사와 구분한다. 모듈 성능은 `artifacts/milestones/M05/evidence/soldier-dynamics-tests.json`의 보존된 결과를 사용한다. 동시 실행한 새 기능 회귀의 시간을 과거 측정 위에 덮어써 성능 변화로 표시하지 않는다.
